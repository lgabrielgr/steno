# M1-07 CI Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make build && make test && make lint` runs on every pull request to `main`, and a red run blocks the merge button.

**Architecture:** One GitHub Actions workflow on a `macos-26` runner. Because a runner has no Personal Team signing identity, CI writes a stub `Local.xcconfig` (XcodeGen refuses to generate without the file) and turns signing down to ad-hoc through a new, CI-unaware `XCFLAGS` variable on the Makefile's single `XCB` definition — the command line being the only level that outranks `project.yml`'s `settings.base`. The check is then wired into `main`'s existing branch protection, by name, only after the name has been observed on a real run.

**Tech Stack:** GitHub Actions, GNU Make 3.81 (Apple's), xcodebuild, XcodeGen, SwiftLint, `gh` CLI.

**Spec:** [`docs/superpowers/specs/2026-09-04-m1-07-ci-workflow-design.md`](../specs/2026-09-04-m1-07-ci-workflow-design.md)

## Global Constraints

- **Never commit to `main`.** All work lands on `chore/ci-workflow`. §9.5.
- **Do not merge the PR.** The user reviews and merges. §9.5 step 7.
- `make build && make test && make lint` must all pass before the PR is opened. §9.5 step 4.
- Commit messages explain *why*, with a Conventional Commits prefix (`feat:`/`fix:`/`chore:`/`docs:`/`test:`/`refactor:`).
- Every commit ends with the trailer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Never commit `Steno.xcodeproj` or `Local.xcconfig`. Both are gitignored; if either appears in `git status`, stop.
- Repo is `lgabrielgr/steno`. Default branch `main`. Branch for this task: `chore/ci-workflow` (already created and holding the spec commit).
- Runner label: `macos-26`. Action pin: `actions/checkout@v7`.
- The CI signing overrides, verbatim and identical everywhere they appear: `CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual`
- The CI stub team, verbatim: `DEVELOPMENT_TEAM = CI0000000`
- Expected check-run name: `build-test-lint` — **treat as a prediction, not a fact.** Task 5 reads the real name and uses that.

### Two environment hazards

- **`origin` must stay SSH** (`git@github.com:lgabrielgr/steno.git`). The `gh` token carries `repo` but **not** `workflow` scope, so pushing `.github/workflows/` over an HTTPS remote would be rejected with "refusing to allow an OAuth App to create or update workflow". Over SSH the push uses the SSH key and the scope is irrelevant. Verify with `git remote -v` before Task 4 if the push fails.
- **`make test` regenerates `Steno.xcodeproj` on every run** (D-014, by design). If Xcode is open on this project, expect it to notice.

### Task 1: The Makefile `XCFLAGS` seam

**Files:**
- Modify: `Makefile` — the `XCB :=` definition (currently at the line beginning `XCB := xcodebuild -project`)

**Interfaces:**
- Consumes: nothing.
- Produces: `make <build|release|test> XCFLAGS='<xcodebuild build settings>'` appends those settings to the xcodebuild command line. Default is empty, so every existing invocation is byte-identical to today's.

**How this task is tested.** There is no Swift code here, so the test is behavioural and observable: with the override passed, the built app's signature must change from the developer's Apple Development identity to `adhoc`. This uses your **real** `Local.xcconfig` — do not create a stub for this task, and do not move that file.

- [ ] **Step 1: Establish the red — prove `XCFLAGS` is currently ignored**

```bash
make build XCFLAGS='CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual' \
  && codesign -dv .build/Build/Products/Debug/Steno.app 2>&1 | grep -E '^Signature|^TeamIdentifier'
```

Expected (the flags go nowhere, so the normal identity is used):

```
Signature=adhoc            <- must NOT appear
```

You should instead see a real signature and a populated `TeamIdentifier=DYMS4937VY`. That is the failing state: Make accepted the variable and xcodebuild never saw it.

- [ ] **Step 2: Add the seam**

Replace the existing single line:

```make
XCB := xcodebuild -project $(PROJECT) -scheme $(SCHEME) -derivedDataPath $(DERIVED)
```

with:

```make
# Extra build settings appended to every xcodebuild invocation. Empty locally,
# so `make build` is unchanged. CI sets it to ad-hoc signing: a runner has no
# Personal Team identity, and §9.3's stable-identity rule exists for local TCC
# persistence, which a runner has no stake in (M1-07, D-053).
#
# This is a Make variable and not a Local.xcconfig key because an xcconfig
# cannot reach CODE_SIGN_IDENTITY: project.yml sets it under settings.base,
# XcodeGen writes that into the .pbxproj, and a .pbxproj build setting outranks
# the xcconfig attached to the same configuration. Measured, not assumed — the
# xcconfig route resolves to "Apple Development" regardless. The xcodebuild
# command line is the only level that wins.
#
# `?=` so a caller's `make build XCFLAGS=...` takes effect while the default
# stays empty.
XCFLAGS ?=
XCB := xcodebuild -project $(PROJECT) -scheme $(SCHEME) -derivedDataPath $(DERIVED) $(XCFLAGS)
```

- [ ] **Step 3: Verify the green**

```bash
make build XCFLAGS='CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual' \
  && codesign -dv .build/Build/Products/Debug/Steno.app 2>&1 | grep -E '^Signature|^TeamIdentifier'
```

Expected:

```
Signature=adhoc
TeamIdentifier=not set
```

- [ ] **Step 4: Verify the default path is unchanged**

The seam must be invisible when unused. Rebuild with no override and confirm the normal identity returns:

```bash
make build && codesign -dv .build/Build/Products/Debug/Steno.app 2>&1 | grep -E '^Signature|^TeamIdentifier'
```

Expected: `Signature=adhoc` is **gone**, `TeamIdentifier=DYMS4937VY` is back. This restores your local build to a normally-signed app; do not skip it.

- [ ] **Step 5: Run the full §9.5 gate**

```bash
make build && make test && make lint
```

Expected: all three exit 0. `make test` ends in `** TEST EXECUTE SUCCEEDED **`.

- [ ] **Step 6: Commit**

```bash
git add Makefile
git commit -F - <<'EOF'
chore: add an XCFLAGS seam to the xcodebuild invocation

M1-07's CI runner has no Personal Team signing identity and cannot acquire
one, so it must build with signing turned down. That override has to arrive on
the xcodebuild command line: project.yml sets CODE_SIGN_IDENTITY under
settings.base, XcodeGen writes it into the .pbxproj, and a .pbxproj build
setting outranks the xcconfig attached to the same configuration — so the
otherwise-obvious route of putting it in Local.xcconfig resolves to
"Apple Development" and is silently ignored.

XCB is defined once and consumed by build, release and test, so one variable
threads the override through every path that compiles. It defaults to empty,
leaving local behaviour byte-identical, and the Makefile stays unaware that CI
exists — this is a general override seam, not a CI branch.

Verified by observation rather than assertion: with the override the built app
reports Signature=adhoc and TeamIdentifier=not set; without it, the normal
Apple Development identity returns.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
EOF
```

### Task 2: The workflow file

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `XCFLAGS` from Task 1.
- Produces: a check run whose name is the job id, `build-test-lint`. Task 5 depends on that name.

- [ ] **Step 1: Create the workflow**

Write `.github/workflows/ci.yml` exactly as below. The comments are part of the deliverable — the task file calls this "one of the few files the user will read without an agent present".

```yaml
# Runs the §9.5 step 4 gate — make build && make test && make lint — on every
# pull request to main, so the rule holds without an agent's cooperation.
# Design and the measurements behind it:
#   docs/superpowers/specs/2026-09-04-m1-07-ci-workflow-design.md
name: CI

on:
  pull_request:
    branches: [main]

# No `paths:` filter, deliberately. A paths-filtered workflow does not run on a
# PR that touches nothing matching, and a *required* check that never reports
# leaves the PR stuck on "Expected — waiting for status to be reported". With
# enforce_admins on, that cannot be self-overridden. A doc-only PR would become
# unmergeable to save a few runner minutes.

# Block style, not flow style: `${{ … }}` is built from `{`, `}` and spaces,
# which are indicators inside a YAML flow mapping. The one-line form
# `concurrency: { group: ci-${{ github.ref }} }` is a hard parse error.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  # This job id is the check-run name, and it is what branch protection's
  # required_status_checks matches on, verbatim. Keep it a plain identifier;
  # adding a `name:` here renames the check and silently breaks that match.
  build-test-lint:
    runs-on: macos-26
    env:
      # Defined once so the build and test invocations cannot drift apart.
      # Ad-hoc rather than CODE_SIGNING_ALLOWED=NO: this way the codesign step
      # actually runs against the app, the embedded StenoKit framework and the
      # test bundle, so a broken Steno.entitlements or an embedding regression
      # fails here instead of reaching main.
      SIGN: CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual
    steps:
      - uses: actions/checkout@v7

      # One line, and it puts the toolchain in every log. When CI and local
      # disagree this is the first thing anyone needs and the most annoying
      # thing to obtain after the fact.
      - name: Toolchain version
        run: xcodebuild -version

      # Local.xcconfig is gitignored (§9.3) and holds a Personal Team ID no
      # runner has. It cannot simply be absent: xcodegen refuses to generate
      # without it ("Invalid config file"), and `make preflight` requires a
      # non-empty DEVELOPMENT_TEAM. The team below is never resolved — SIGN
      # selects CODE_SIGN_STYLE=Manual, which performs no profile lookup and so
      # makes no Apple ID round-trip.
      - name: Write CI signing stub
        run: printf '// Generated by CI. Not a real team.\nDEVELOPMENT_TEAM = CI0000000\n' > Local.xcconfig

      - name: make bootstrap
        run: make bootstrap

      - name: make build
        run: make build XCFLAGS="$SIGN"

      # Runs headless with outbound networking denied by Scripts/test-sandbox.sb
      # (§9.4, D-012). Needs no credentials, which is why this workflow needs no
      # secrets.
      - name: make test
        run: make test XCFLAGS="$SIGN"

      - name: make lint
        run: make lint
```

- [ ] **Step 2: Append the record**

```markdown
### D-053 — CI signs ad-hoc, through an `XCFLAGS` seam rather than an xcconfig key
**2026-09-04** · M1-07 · **Status:** accepted

`make build`, `make test` and `make release` pass `$(XCFLAGS)` — empty by default — to
`xcodebuild`. CI sets it to `CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual` and writes a stub
`Local.xcconfig` carrying `DEVELOPMENT_TEAM = CI0000000`. `main`'s branch protection requires the
resulting `build-test-lint` check, with `strict: false`.

**Why an xcconfig key does not work:** `project.yml` sets `CODE_SIGN_IDENTITY` under
`settings.base`; XcodeGen writes that into the `.pbxproj`; and a `.pbxproj` build setting outranks
the xcconfig attached to the same configuration. Putting the override in `Local.xcconfig` resolves
to `Apple Development` and is ignored — measured with `-showBuildSettings`, not assumed. The
xcodebuild command line is the only level that wins, so the seam has to be a Make variable.

**Why the stub file is needed at all:** `Local.xcconfig` is gitignored, so a fresh checkout lacks
it — and `xcodegen generate` then fails outright with `Invalid config file "Local.xcconfig"`. CI
cannot simply build without one. `preflight` is left unmodified and the stub satisfies it as
written: teaching `preflight` to stand down when `CI` is set would weaken the gate exactly where
nobody is watching.

**Why ad-hoc rather than `CODE_SIGNING_ALLOWED=NO`:** both build and test green, but ad-hoc still
runs the codesign step over the app, the embedded `StenoKit` framework and the test bundle, and
embeds the entitlements — verified with `codesign -dv --entitlements -`. So a broken
`Steno.entitlements` or a framework-embedding regression fails CI instead of reaching `main` and
surfacing on the next local build. This does not weaken §9.3: its stable-identity rule exists so
macOS TCC grants survive rebuilds, and a runner holds no TCC grants. `XCFLAGS` defaults to empty
and `project.yml` still pins `Apple Development`, so local signing is untouched.

**Why `strict: false`:** `strict: true` also requires a branch be up to date with `main` before
merging, forcing a rebase every time `main` moves. The race it protects against needs concurrent
merges to arise; with one developer merging sequentially it is friction bought for nothing.

**Alternatives:** indirection in `project.yml` (`CODE_SIGN_IDENTITY: $(STENO_SIGN_IDENTITY)`) —
rejected because an existing `Local.xcconfig` lacking the new key resolves it to empty and
silently changes how local builds sign, which is precisely what §9.3 forbids; a `CI`-conditional
`Makefile` — rejected because the build system would then behave differently where nobody is
watching.
```
