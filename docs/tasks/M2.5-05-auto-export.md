# M2.5-05 — Auto-Export

**Milestone:** M2.5 — Portability
**Depends on:** M2.5-04
**Blocks:** M2.5 exit criterion
**Requirements:** §10.5, FR-6, §8
**Branch:** `feat/auto-export`

## Goal

Automatic export to a user-chosen folder — on quit or daily — **defaulting ON**, surfaced
during onboarding rather than buried in settings.

## In scope

- Setting: enable/disable, target folder, trigger (on quit and/or daily).
- **Default ON** (§10.5, v1.5 changelog). This is deliberate, not an oversight.
- Onboarding step introducing it, with the cloud-drive suggestion (Dropbox, Google Drive,
  iCloud Drive).
- Sensible retention so the folder does not grow without bound.
- Failure handling: a failed auto-export must be visible, not silent.

## Out of scope

- Export/import mechanics — M2.5-01, M2.5-02.
- Real-time sync. Cancelled (D1, §14). This is a substitute, and an honest one.

## Acceptance criteria

- [ ] Enabled by default on a fresh install, with the folder chosen during onboarding.
- [ ] On the configured trigger, a valid export appears in the target folder.
- [ ] Export on quit does not delay quit noticeably or lose data if the app is force-quit.
- [ ] A failure (folder missing, permissions revoked, disk full) surfaces to the user rather
      than failing silently.
- [ ] The exported file still contains no secrets (§10.3) — this path writes automatically and
      unattended, so the assertion matters more here, not less.
- [ ] Sandbox/permission handling for a user-chosen folder persists across relaunch.

## Notes for the spec/plan phase

- **This is the backup story as well as the transfer story** (§10.5). With sync cancelled and
  no remote copy anywhere, an unnoticed auto-export failure means the user has no backup and
  does not know it. Silent failure is the one unacceptable behavior here.
- §10.5 is candid about the limit: pointing the folder at a cloud drive gives "most of the
  value of sync for zero cost," but not real-time convergence — a machine must export before
  the other imports. Given single-user, one-machine-at-a-time usage, that gap is largely
  theoretical. Do not try to close it; closing it is §14's cancelled work.
- Default-ON exists because "manual export's failure mode is human: forgetting to run it."
  Keep it opt-*out*.
- Whether this is genuinely sufficient in daily practice is **open question Q(M2)** in §12. If
  the answer turns out to be no, that reopens §14 — a product decision, not an implementation
  one. Report the experience; do not build sync.
