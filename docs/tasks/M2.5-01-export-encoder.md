# M2.5-01 — Export Encoder

**Milestone:** M2.5 — Portability
**Depends on:** M2-04
**Blocks:** M2.5-02
**Requirements:** §10.2, §10.3, §8
**Branch:** `feat/export-encoder`

## Goal

Serialize the entire store to a single, human-readable JSON file containing no secrets.

## In scope

- The §10.2 envelope: `schemaVersion`, `exportedAt`, `exportedBy`,
  `includesCachedExternalData`, then `projects`, `tasks`, `events`, `sourceRefs`, `reports`.
- `sourceRefs` as its own top-level array keyed by `taskID` (v1.7 — refs are records with
  identities, not fields of a task).
- `cachedSummary` and `lastFetchedAt` excluded by default; included only when
  `includesCachedExternalData` is set.
- Filename convention `steno-export-YYYY-MM-DD.json`.

## Out of scope

- Import — M2.5-02.
- UI and CLI surfaces — M2.5-03, M2.5-04.
- Gzip. §10.2 permits it if size warrants, but plain JSON is canonical and D18 caps scale at
  under 20 live tasks.

## Acceptance criteria

- [ ] Round-trip fidelity: every field of every model survives export (verified once M2.5-02
      lands; write the export side to make it possible).
- [ ] **The export contains no string matching known credential patterns.** §10.3 requires this
      be asserted *in a test*, not argued from construction — "the failure mode is a work token
      sitting in a file the user AirDrops or drops in a shared folder."
- [ ] `schemaVersion` is present and correct.
- [ ] By default, `cachedSummary` and `lastFetchedAt` are absent while the `sourceRefs` array
      itself is still present.
- [ ] Output is human-readable, greppable, and diffable — stable key order, indented.

## Notes for the spec/plan phase

- **This is now the only way Steno moves between machines, permanently** (§10, D1). Sync is
  cancelled, so treat M2.5 as core rather than optional. An export that quietly drops a field
  loses user data with no other copy to recover from.
- Secrets are excluded *by construction* — §8 keeps them in Keychain, and the export serializes
  SwiftData only. §10.3 still demands the test, because construction-based guarantees erode
  silently when someone later adds a field.
- Integration *configuration* (site URLs, MCP server definitions minus secrets) may be
  exported, with the target machine prompting for credentials on first use (§10.3). Decide
  whether that lands here or with M4-04/M5-02 and say so in the PR body.
- Stable ordering makes exports diffable, which makes the auto-export in M2.5-05 a genuine
  backup history rather than noise.
