# M2.5-03 — Import Preview & Replace Mode

**Milestone:** M2.5 — Portability
**Depends on:** M2.5-02
**Blocks:** M2.5-04
**Requirements:** §10.4, §10.1, §10.5
**Branch:** `feat/import-preview-ui`

## Goal

File → Export… / Import… with a cancellable preview of exactly what an import will change, plus
a guarded Replace mode.

## In scope

- Standard save/open panels for export and import (§10.5).
- A preview summary before committing, in the shape §10.4 specifies:

```
Import steno-export-2026-08-10.json?
  + 12 new tasks, 3 new projects, 148 new events
  ~ 4 tasks updated (status changed on the other machine)
  = 61 records already present, skipped
```

- Cancel leaves the store untouched.
- **Replace mode**, explicitly labeled and separate from merge: wipes the local store first,
  requires **typed confirmation**, and **auto-exports a backup beforehand** (§10.1).

## Out of scope

- Merge logic — M2.5-02.
- CLI — M2.5-04.
- Auto-export scheduling — M2.5-05.

## Acceptance criteria

- [ ] The preview's counts match what the import actually does. A preview that under-reports is
      worse than no preview.
- [ ] Cancelling changes nothing.
- [ ] Import applies in a single transaction (§10.4).
- [ ] Replace mode requires typed confirmation — not a single click, not a default-focused
      destructive button.
- [ ] Replace mode writes a backup export **before** wiping, and fails safe if that backup
      cannot be written.
- [ ] Merge remains the default. Replace is never the path of least resistance.

## Notes for the spec/plan phase

- §10.1: Replace "exists for restoring a known-good snapshot, not for routine transfer." The UI
  should make that obvious — merge is the everyday action, Replace is the break-glass one.
- The preview is the user's only chance to inspect before committing, and §10.2 chose plain
  JSON partly so a file can be inspected beforehand. Make the summary specific enough to catch
  importing the wrong file.
- The backup-before-replace is a real safety requirement, not a nicety: Replace is the only
  destructive operation in the product, and with sync cancelled there is no remote copy.
