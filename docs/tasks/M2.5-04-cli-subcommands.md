# M2.5-04 — CLI Export/Import Subcommands

**Milestone:** M2.5 — Portability
**Depends on:** M2.5-03
**Blocks:** M2.5-05
**Requirements:** §10.5, §9
**Branch:** `feat/cli-export-import`

## Goal

`steno export` / `steno import` on the app binary, plus `make export FILE=…` and
`make import FILE=…`, making the round-trip scriptable and testable.

## In scope

- Argument parsing on the app binary so it can run headless as a CLI without launching the UI.
- `steno export [--output PATH] [--include-cached]`
- `steno import --file PATH [--replace]`
- `make export FILE=…` and `make import FILE=…` wrapping them.
- Non-zero exit on failure, consistent with §9.2's rule for every make target.

## Out of scope

- New export/import semantics. This task is a surface over M2.5-01 and M2.5-02 — it must not
  fork their behavior.
- Interactive prompts. Replace mode's typed confirmation is a GUI affordance; the CLI uses an
  explicit `--replace` flag.

## Acceptance criteria

- [ ] `steno export` writes a file identical to what the GUI produces for the same store.
- [ ] `steno import` merges identically to the GUI path.
- [ ] Both exit non-zero on failure with a message on stderr.
- [ ] Running a subcommand does not open a window or require a GUI session.
- [ ] A full round-trip is exercised in `make test` (§10.6).

## Notes for the spec/plan phase

- §10.5 wants this "consistent with §9's CLI-first stance and makes the round-trip scriptable
  and testable." The testability is the real prize: this is what lets §10.6's round-trip
  properties be verified end to end rather than only at the unit level.
- A GUI `.app` bundle taking argv is slightly unusual on macOS. Decide early how the binary
  distinguishes CLI invocation from a normal launch, and make sure a double-click never lands
  in CLI mode.
- Keep the flag surface small. This is a personal tool, not a distributed CLI.
